# Miranda Parser Architecture and Subsystem Reference

This document provides a comprehensive overview of the design, grammar parsing rules, codegen mappings, and testing strategies for the pure-Zig parser in Miracula.

---

## 1. Subsystem Architecture

The parser subsystem is located in `src/parser/` and operates as a unified compiler pipeline:

```text
source text ([:0]const u8)
  ├──> lex.zig (Lexical Analyzer)
  ├──> lex_bridge.zig (Tokenize Bridge) ──> []Token
  ├──> pratt.zig & parser.zig (Pratt + RD Parser) ──> ast.Script
  └──> codegen.zig (AST Codegen) ──> Emits Word heap cells to C-runtime
```

### Component Roles
* **`lex.zig`**: Scans characters, resolves layout-sensitive offside rules, handles indentation stacks, and injects `OFFSIDE` and `ELSEQ` layout tokens.
* **`lex_bridge.zig`**: Scans the lexer to produce a slice of `Token` structures containing line and column span metadata.
* **`ast.zig`**: Defines the target Abstract Syntax Tree (AST) using pure-Zig tagged unions. It is stateless, memory-efficient, and does not require C-runtime structures.
* **`token_filter.zig`**: Defines token types, vocabulary, and filters.
* **`pratt.zig`**: Implements a Pratt expression parser with binding-powers matching the Miranda operator precedence table.
* **`parser.zig`**: Implements a recursive-descent parser for script structure, type signatures, algebraic definitions, and exports. Implements item-level error synchronization to continue parsing after syntax errors.
* **`codegen.zig`**: Traverses the AST and constructs the corresponding graph nodes in the Miranda cell heap.

## 2. Operator Precedence and Binding Powers

Miranda expression parsing uses a Pratt parser with the following operator precedence table (from lowest to highest precedence):

| Operator(s) | Associativity | Binding power |
|---|---|---|
| `\/` (vel / OR) | Right | 20 |
| `&` (AND) | Right | 30 |
| `= ~= < > <= >=` | Left | 40 |
| `: ++ --` (Cons, append, subtract list) | Right | 50 |
| `+ -` | Left | 60 |
| `* / div mod` | Left | 70 |
| `^` (power) | Right | 79 |
| `.` (function composition) | Left | 80 |
| `!` (list subscript) | Left | 90 |
| Application (juxtaposition) | Left | 100 |

## 3. Codegen AST-to-Heap Mappings

`codegen.zig` compiles the stateless AST representation into the active heap graph structure expected by the reduction engine.

| Construct | Heap encoding |
|---|---|
| `name` / `cname` | `sto_id(text)` |
| Integer literal | `bigscan(decimal_text)` |
| Float literal | `sto_dbl(val)` |
| Char literal | `sto_char(codepoint)` |
| String literal | Right-fold `make(CONS, sto_char(c), ...)` from `NIL` |
| Application | `make(AP, func, arg)` |
| Infix operator | `ap2(opWord(op), lhs, rhs)` |
| Infix `!` (subscript) | `ap2(SUBSCRIPT, rhs, lhs)` *(Arguments reversed)* |
| Infix `:` (cons) | `make(CONS, lhs, rhs)` |
| Negation (`-x`) | `ap(NEG, inner)` |
| List length (`#x`) | `ap(LENGTH, inner)` |
| Empty list `[]` | `NIL` |
| List `[a, b, c]` | Right-fold `make(CONS, elem, acc)` from `NIL` |
| Tuple `(a, b)` | `make(PAIR, a, b)` |
| Tuple `(a, b, c)` | `make(TCONS, a, make(PAIR, b, c))` |
| Where clause | `block(local_defs, body, 0)` |
| Section Left `(e op)` | `ap(opWord(op), e)` |
| Section Right `(op e)` | `ap2(C, opWord(op), e)` |
| Section Op `(+)` | `opWord(op)` |
| List comprehension | Qualifiers reversed; `compzf(body, qualifiers, 0)` |
| Range `[a..b]` | `ap3(STEPUNTIL, big_one, b, a)` |
| Range `[a..]` | `ap2(STEP, big_one, a)` |
| Range `[a,b..c]` | `ap3(STEPUNTIL, ap2(MINUS,b,a), c, a)` |
| Range `[a,b..]` | `ap2(STEP, ap2(MINUS,b,a), a)` |

## 4. Testing and Snapshot Strategy

To verify parser behavior, a snapshot-testing runner is implemented in `tests/mira_tests.zig` and `src/parser/parser_tests.zig`.

### 4.1. Snapshot Files
Goldens are recorded under `tests/parser/snapshots/*.snapshot`. Each snapshot verifies:
- The token stream generated by the lexer.
- The syntax tree construction structure.
- Successful completion or error diagnosis matching.

### 4.2. Run & Update Commands
* **Run tests**:
  ```bash
  zig build test
  ```
* **Update snapshots** (when syntax additions are made):
  ```bash
  UPDATE_SNAPSHOTS=1 zig build test
  ```
